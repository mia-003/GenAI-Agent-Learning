# W1 · 每日学习安排

[[01-学习计划/周任务/W01|本周任务与验收]] · [[学习工作台|工作台]] · [[03-学习笔记/章节/01-Agent入门|本周笔记]]

起始日：2026-11-03。D1–D7是建议顺序，对应11月3–9日；每天约120分钟，共14小时。时间可以拆分或挪动，不因某天未完成就重开一周。

## 本周要达到什么程度

能自己解释并实现一个最小Agent：模型读取上下文，选择工具，程序执行工具，结果返回模型，再决定继续或停止。能用实际轨迹区分“结束了”和“做对了”，并解释一次失败。

本周阅读引言和第1章；官方实验优先做1-1 context，再做自己的单工具循环。其他第1章实验暂作选读。对第2、7章的概念仅建立直觉，后续再系统学习。

## D1 · 今天：先建立正确的概念（120分钟）

### 0–25分钟：读引言，知道这本书要解决什么

打开 [[02-教材/中文正文/introduction|引言]]，重点读开头、全书结构、如何阅读本书和前置知识。产品故事与致谢可以略读。

带着两个问题：

- 我最终要理解和构建的系统是什么？
- 为什么使用更强的模型，并不能代替全部系统设计？

只记录关键词，不要整段摘抄，不需要补完全部前置知识再开始。

### 25–90分钟：读第一章的三要素

打开 [[02-教材/中文正文/chapter1#现代 Agent = LLM + 上下文 + 工具|第一章 · 现代 Agent = LLM + 上下文 + 工具]]。

按顺序阅读：观察空间与动作空间 → 工具 → LLM → 上下文。今天在“ReAct循环”前停下；可以预览，不要求读完。

回答：

1. LLM决定什么，工具真正执行什么？
2. 上下文除用户问题外，还包含什么？
3. 观察空间、动作空间与策略分别对应什么？先理解直觉，不推数学。
4. 一次普通聊天与一个能够行动的Agent，在运行过程上有什么区别？

### 90–120分钟：合上书，产出自己的解释

在 [[03-学习笔记/章节/01-Agent入门|01-Agent入门]] 的“我的理解”中完成：

- 用自己的话写100–200字：Agent由什么组成，它怎样影响外部环境？
- 画一张图：用户目标 → 上下文 → LLM → 工具执行 → 工具结果回到上下文。
- 选择一个自己用过的产品，分别指出它能观察什么、能做什么、由什么决定下一步。
- 写3个尚不理解的问题。
- 在工作台保存今天的实际学习分钟和下一步。不预填120分钟；按实际投入填写。

今天完成标准：不用照抄书，也能给一个会Python的人讲清楚三要素，并给出具体例子。今天无需安装依赖或申请API Key，也不要提前勾选W1整项“阅读完成”。

## D2 · 深入ReAct与消息流（120分钟）

### 阅读75分钟

精读 [[02-教材/中文正文/chapter1#ReAct 循环|ReAct循环]]；需要时回看“上下文”。关注任务目标、当前观察、下一动作、工具结果、终止响应。

理解ReAct描述的是决策—行动—观察的循环。不要把它等同于必须看到模型完整的内部思考；能检查的是实际发送的消息、动作和返回结果。

### 手工模拟30分钟

用“计算三件商品折扣后的总价”模拟：

1. 用户给出价格、数量和折扣规则。
2. 模型根据已有信息决定是否调用计算工具。
3. 程序执行工具，获得数值或错误。
4. 把工具结果放回上下文。
5. 模型继续调用或给出最终结果。

为每一步标注：谁负责？输入是什么？输出是什么？如果工具结果丢失，下一轮缺少什么信息？这里只是纸面/伪代码模拟，不算真实API实验。

### 复述15分钟

闭卷解释：为什么必须回传工具结果？为什么要限制轮数？为什么“模型说完成”不等于真的完成？记录到章节笔记。

## D3 · Harness、工作流与环境准备（120分钟）

### 阅读75分钟

阅读第一章剩余正文：Harness工程、构建原则、模型选择、工作流与自主编排、护栏、贯穿全书的设计模式和本章小结。前沿产品案例与复杂引用可略读，标出后续回看项。

重点写清楚：

- 上下文管理、工具接口、约束、验证、纠正各负责什么。
- 哪种任务适合固定工作流，哪种需要自主决策；混合方式有什么价值。
- 什么条件应该继续、重试、停止或交还用户。

章末思考题：本周优先第1、3、4、5、6题；其余标记为后续复习，先独立作答再查参考答案。

### 环境与入口检查45分钟

官方代码位于本地隐藏目录 `.materials/ai-agent-book/`。先读根README与 `chapter1/context/README.md` 的“理解问题与方法”“准备环境与输入”和运行入口。

检查Python版本、虚拟环境、单章依赖和所需模型配置；只配置本周需要的环境。API提供商与预算尚未确定，可到这一步再一起选择；不要把凭据写进笔记或GitHub。

交付：一张Harness职责表，以及可运行环境或阻塞清单。环境未准备好时标注“未运行”，不要为赶进度宣称实验完成。

## D4 · 跑通官方context实验（120分钟）

### 前60分钟：先跑一个完整上下文任务

按该实验README选最小入口；先确认完整模式，不一开始跑大批量。保存任务、模型/版本、消息、工具调用、工具返回、停止原因和结果。

遇到问题先区分：依赖、凭据、模型/provider配置、外部网络、工具逻辑。环境排查超过60分钟，剩余时间改读仓库保留的轨迹，另记“历史证据分析”，随后补跑真实实验。

### 后60分钟：解释轨迹，再做一个消融

选完整模式与“移除工具结果”模式比较，其他条件保持一致。理解占位符也会提供额外信息，不能与静默隐藏结果混为一谈。

逐轮解释：模型实际看到了什么？是否真的执行了工具？结果有没有返回？为什么继续或终止？

交付：至少一条可解释的轨迹，以及一个对照。区分 `completed`（循环结束）与任务做对；单次现象不作为普遍结论。记录来源、实跑或历史分析状态。

## D5 · 自己实现最小单工具循环（120分钟）

### 实现105分钟

在「05-项目实践/W01-最小Agent」创建自己的小项目（到这一天再建）。先写预期行为，再请AI帮助实现。工具只做有边界的算术，不执行任意生成代码。

必须具备：

- 消息列表、一个计算工具定义、模型调用、工具分发、结果回传、循环和最终回答。
- 参数检查、工具错误回传、最大轮数与明确停止原因。
- 可检查的日志；API凭据从本地配置读取，不写进源码。
- 独立核对结果的代码或人工真值，不接受模型自评作为唯一验证。

先手工走一遍设计，再看AI给出的实现。每个核心步骤都能由你解释；不要求背SDK。

### 固定任务15分钟

为D6准备下面5条任务，先写好预期结果，不看实验输出改答案。固定模型、参数、输入与工具能力。

| 编号 | 任务类型 | 示例 | 预期行为 |
| --- | --- | --- | --- |
| T1 | 单步计算 | 238×47 | 得到11186 |
| T2 | 多步计算 | 单价129、数量3、九折，再减20 | 得到328.3，顺序正确 |
| T3 | 约束与精度 | 99.99×7，先减50再九五折，最终四舍五入到分 | 得到617.43；明确舍入位置 |
| T4 | 信息不足 | 三件商品打九折后多少钱，但未给单价 | 要求补充单价，不能编造 |
| T5 | 工具错误 | 计算10÷0 | 明确未定义/不可计算，不无限重试、不伪造数值 |

这些是机制检查用的小样本，不是展示模型整体能力的基准。

## D6 · 对照、失败与证据（120分钟）

- 60分钟：在自己的同一套Agent与同一批5题上，比较启用计算工具/不提供工具两种条件。共10次基础运行，不与官方实验的不同任务混算。
- 40分钟：挑选结果不一致、出现错误或有随机性的一两题复跑；定位第一个错误。不要求工具组一定更好；算术题可能两组都正确。
- 20分钟：整理结果表，列出能支持和不能支持的结论。

记录列：任务、条件、实际答案、真值/预期行为、是否通过、工具调用、停止原因、耗时、调用成本（能获取时）与证据路径。

至少解释一个失败或边界案例：错在决策、参数、执行、回传、终止还是验证？如全部正确，用“结果缺失/工具报错”的受控故障检查恢复行为，单独标注为故障注入，不与基线混算。

## D7 · 补齐与闭卷验收（120分钟）

### 补齐对照45分钟

完成未完成的对照、检查结果与证据对应关系，纠正过强的结论。不要把今天变成新增功能日。

### 闭卷复述15分钟

重新画循环，并写3个准备带到W2的问题。

### 验收60分钟

- 15分钟：不看书，解释三要素与Harness；区分工作流和自主Agent。
- 15分钟：拿一条真实轨迹，逐轮说明模型看到了什么、执行了什么、为什么停止。
- 15分钟：演示正常输入、信息不足、工具错误和轮数限制，检查实际结果。
- 15分钟：整理本周笔记、代码、对照表和待解问题，按交付情况勾选W01五项任务。

最终交付：章节笔记＋最小Agent＋官方实验记录＋五题对照表＋本周结论。如果有任务未完成，保留未勾选并顺延；不以耗满14小时代替验收。
