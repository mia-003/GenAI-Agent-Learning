# AI Agent 学习路线：原理理解与工程作品

制定日期：2026-11-02（America/Los_Angeles）

## 你的起点与目标

- 已有 Python 基础，能读代码，复杂系统可结合讲解学习。
- 每周约 14 小时，每天时间不固定。
- 主目标：理解机制、设计原因、适用条件和失效边界。
- 次目标：独立完成一个有实际用途、能在求职面试中解释和展示的 Agent 项目。
- 建议周期：16 个学习周，约 224 小时。周次表示任务包，不绑定自然周；未完成的内容可顺延。
- 全面理解分层进行：第一轮覆盖十章核心机制；后训练的大规模复现和机器人实机不作为第一轮必做项。16 周不等于精通全部研究方向。

## 阅读路线与理由

引言 → 第1章 → 第2章 → 第4章 → 第3章 → 第5章 → 第7章 → 第9章 → 第6章 → 第10章 → 第8章 → 综合项目。

先理解循环与上下文，再建立工具接口与知识系统；用评估判断改动，再讨论进化、交互、协作与训练。第7章的基本评估思想从第1周就开始使用。第2章分两周，第3章分两周；项目从第1周逐步积累，第14–16周集中整合。

## 每周14小时：按任务块安排

| 任务块 | 总时间 | 做法 |
|---|---:|---|
| 原理阅读 | 4小时 | 可拆为4×60分钟；阅读正文，关注状态、接口与约束 |
| 实验实现 | 5小时 | 可拆为2×2小时+1小时；先做最小实现，再对照官方代码 |
| 对照与失败分析 | 3小时 | 固定输入，只改变一个变量，保留所有结果 |
| 笔记与收尾 | 2小时 | 自由整理笔记和例子，阅读简短批注，更新进度 |

30分钟碎片时间适合复习、读一个小节、检查一段轨迹；连续90–120分钟用于实验和调试。不要求每天恰好2小时。每周最后检查交付物，未完成时优先补机制与验证，减少扩展实验。

## 推荐毕业项目：可审计的数据分析 Agent（方向暂定）

这是项目建议，尚未假定你的求职岗位或数据背景。到第4周结合兴趣确定业务；数据分析、业务分析、供应链场景都可承载同一架构。

### 真实问题

用户提出业务问题后，系统需要读取数据字典、查验数据、生成并执行受控查询，最后提供有来源、可复核的结论。对于定义不清、缺列、空数据、重复记录、错误口径等情况，应给出明确处理结果。

### 最小范围

- 本地小型SQLite业务数据库与Markdown指标说明；使用合成或公开数据。
- 只读SQL与独立执行限制；任务目标、schema与关键指标定义进入上下文。
- 问题澄清→检索定义→生成查询→执行→检查→回答；设置超时、步数和预算上限。
- 输出查询、数据来源、关键计算、结论和不确定性，保存必要轨迹。
- 核心循环先自己写，后续按需要引入框架，确保能解释抽象层下发生了什么。

### 有门槛的部分

- 独立验证数值和最终状态，不能让生成者自行批准所有结果。
- 区分需求歧义、检索失败、SQL错误、数据问题和解释错误。
- 从失败轨迹提出小范围规则更新，经过回归后才启用。
- 用消融比较证明模块是否有贡献；多Agent和长期记忆仅在任务确有需要时保留。

### 评估设计建议

- 最终目标约60–100条任务，数量按实现能力调整；早期从15–20条起步。
- 覆盖普通查询、多步分析、口径歧义、缺失/重复数据、无答案、提示注入、工具故障。
- 开发集与最终留出集分离，按任务模板或数据实例划分，避免仅改写问句造成泄漏。
- 对比：固定SQL/规则基线、直接模型方案、你的Agent；固定数据、模型版本和运行条件。
- 数字与执行结果优先用程序验证；定性解释可以辅以人工或Judge，记录其局限。
- 报告任务成功率、数值正确率、无答案处理、成本、延迟，以及每种失败的案例。
- 小样本或单次结果只作为探索证据，不宣称统计显著；对随机性明显的任务安排重复运行。

### 面试交付物

README、架构图、可复现命令、环境版本、样例输入输出、评估集说明、消融表、失败与修复记录、3–5分钟演示。展示自己做了什么、为什么这样设计、证据是什么、尚有什么限制。简历只写实测结果，完成前不预填提升百分比。

## 与AI协作的方法

读不懂时提供文件路径/小节及你当前的理解，要求先用具体例子解释，再对应到实现。让AI帮助实现和调试，但由你先提出预期行为，再验收实际结果。每章只维护一份自由笔记，我会按需要添加简短小号红字批注；读完即可标记当天完成。无需问答、闭卷测试或改写作业。
